# ISO 13485 认证文档助理

## 概述

此技能可帮助医疗器械制造商为 ISO 13485:2016 认证准备全面的文档。它提供了创建、审查和差距分析所有必需的质量管理体系 (QMS)文档的工具、模板、参考和指南。

* *此技能提供什么：**
- 现有文档的差距分析
- 所有强制性文档的模板
- 全面的需求指南
- 逐步创建文档
- 缺失的识别文档
- 合规检查表

* *何时使用此技能：**
- 启动 ISO 13485 认证流程
- 根据 ISO 13485
- 进行差距分析
- 创建或更新 QMS 文档
- 准备认证审核
- 过渡从 FDA QSR 到 QMSR
- 与 EU MDR 要求协调

## 核心工作流程

### 1. 评估当前状态（差距分析）

* *何时开始：** 用户拥有现有文档并需要识别差距

* *流程：**

1. **收集现有文档：**
  - 要求用户提供当前 QMS 文档的目录
  - 文档可以是任何格式（.txt、.md、.doc、.docx、.pdf）
  - 包括任何程序、手册、工作说明、表格

2. **运行差距分析脚本：**
 ```bash
 python script/gap_analyzer.py --docs-dir <path_to_docs> --output gap-report.json
 ```

3. **审核结果：**
  - 确定存在 31 个必需程序中的哪一个
  - 确定缺失的关键文档（质量手册、MDF 等）
  - 计算合规百分比
  - 优先考虑缺失的文档

4. **向用户呈现调查结果：**
  - 总结存在的内容
  - 清楚列出缺少的内容
  - 提供优先的行动计划
  - 估计所需的工作量

* *输出：**包含优先行动项目的综合差距分析报告

### 4. 制定具体文件

#### 创建质量手册

* *流程：**

1. **阅读综合指南：**
  - 完整阅读 `references/quality-manual-guide.md`
  - 了解结构和所需内容
  - 查看提供的示例

2. **收集组织信息：**
  - 法定公司名称和地址
  - 产品类型和分类
  - 组织结构
  - 适用法规
  - 经营范围
  - 任何需要的排除

3. **使用模板：**
  - 以 `assets/templates/quality-manual-template.md`
 开头 - 严格遵循结构（ISO 13485 要求）
 - 替换所有占位符

4. **完成所需部分：**
  - **第 0 节：** 文档控制、批准
  - **第 1 节：** 简介、公司概述
  - **第 2 节：** 范围和排除（关键 - 必须证明排除的合理性）
  - **第 3 节：** 质量政策（必须由高层签署）管理）
  - **第 4-8 节：** 在政策层面解决每个 ISO 13485 条款
  - **附录：** 程序列表、组织结构图、流程图、定义

5. **关键要求：**
  - 必须引用所有 31 个记录程序（附录 A）
  - 必须描述流程交互（附录 C - 创建流程图）
  - 必须定义文档结构（第 4.2 节）
  - 必须证明任何排除的合理性（第 2.4 节）

6. **验证清单：**
  - [ ] ISO 13485 第 4.2.2 条要求的所有内容
  - [ ]由最高管理层签署的质量政策
  - [ ]所有排除合理
  - [ ]附录中列出的所有程序 A
  - [ ]包括流程图
  - [ ]包括组织结构图

#### 创建程序（SOP）

* *所有程序的一般方法：**

1. **了解要求：**
  - 阅读 `references/iso-13485-requirements.md`
 中的相关条款 - 了解必须记录哪些内容
 - 确定您的组织的人员、时间和地点

2. **使用模板结构：**
  - 遵循 CAPA 或文档控制模板作为示例
  - 标准部分：目的、范围、定义、职责、程序、记录、参考文献
  - 保持程序清晰且可操作

3. **明确定义职责：**
  - 确定特定角色（不是名称）
  - 定义每个角色的职责
  - 确保覆盖所有必需的活动

4. **记录“什么”而不是过多的“如何”：**
  - 程序应定义必须做什么
  - 详细的操作方法包含在工作说明（第 3 层）中 
  - 在指导和灵活性之间取得平衡

5. **包括必需的元素：**
  - ISO 13485 条款中指定的所有元素
  - 必须维护的记录
  - 每项活动的职责
  - 相关文档的引用

  * *示例：创建 CAPA 程序**

1. 阅读参考文献 
2 中的 ISO 13485 条款 8.5.2 和 8.5.3。使用`assets/templates/procedures/CAPA-procedure-template.md`
3. 自定义：
  - 您的组织的 CAPA 优先级标准
  - 您将使用的根本原因分析方法
  - 审批机构和责任
  - 基于您的操作的时间表
  - 与投诉处理、审计等集成。
4. 添加表格作为附件：
  - CAPA 请求表
  - 根本原因分析工作表
  - 行动计划模板
  - 有效性验证清单

#### 创建医疗器械文件 (MDF)

* *什么是 MDF：**
- 每种医疗器械类型或的文件系列
- 取代单独的DHF、DMR、DHR（根据FDA QMSR 协调）
- 包含有关设备的所有文档

* *按照ISO 13485 第4.2.3 条要求的内容：**

1. 一般说明和预期用途
2. 标签及使用说明规格
3. 产品规格
4. 制造规格
5. 采购、制造、维修程序
6. 测量和监测程序
7. 安装要求（如适用）
8. 风险管理文件
9. 验证和确认信息
10. 设计和开发文件（如适用）

* *流程：**

1. 识别每个器件类型或系列
2. 创建 MDF 结构（文件夹或活页夹）
3. 收集或创建每个所需元素
4. 确保文件之间的可追溯性
5. 维护为动态文档（随更改更新）

### 5. 进行全面差距分析

* *何时使用：** 用户希望对所有要求进行详细评估

* *过程：**

1. **使用综合清单：**
  - 打开 `references/gap-analysis-checklist.md`
  - 逐条进行工作
  - 标记每个要求的状态：合规、部分、不合规、N/A

2. **对于每个条款：**
  - 阅读需求描述
  - 识别现有证据
  - 注意差距或缺陷
  - 定义所需的操作
  - 分配责任和目标日期

3. **按条款总结：**
  - 计算每个条款的合规百分比
  - 识别最高风险差距
  - 确定行动的优先级

4. **创建行动计划：**
  - 列出所有差距
  - 优先级：关键>高>中>低
  - 分配所有者和日期
  - 估计所需资源

5. **输出：**
  - 已完成的差距分析清单
  - 包含合规百分比的摘要报告
  - 优先行动计划
  - 时间表和里程碑

## 常见场景

### 场景1：从头开始

* *用户请求：**“我们是一家医疗器械初创公司，需要实施 ISO 13485。我们从哪里开始？”

* *方法：**

1. **解释整个过程：**
  - ISO 13485 需要全面的 QMS 文档
  - 通常需要 6-12 个月才能完全实施
  - 可以增量完成

2. **从基础开始：**
  - 质量方针和目标
  - 质量手册
  - 组织结构和职责

3. **遵循优先级顺序：**
  - 使用上面的阶段 1-6 优先级列表
  - 按逻辑顺序创建文档
  - 基于先前创建的文档

4. **关键里程碑：**
  - 第 1-2 月：基础文件（质量手册、政策）
  - 第 3-4 月：核心流程（CAPA、投诉、审核）
  - 第 5-6 月：产品实现流程
  - 第 7-8 月：支持流程
  - 第 9-10 月：内部审核和细化
  - 第 11-12 个月：管理评审和认证审核

### 场景 2：现有 QMS

* *用户请求：** “我们有一些程序，但不知道 ISO 13485 缺少什么。”

* *方法：**

1. **运行自动差距分析：**
  - 请求文档目录
  - 运行`scripts/gap_analyzer.py`
  - 查看自动结果

2. **进行详细评估：**
  - 针对用户的具体情况使用全面的检查表
  - 比自动分析更深入
  - 评估现有文档的质量，而不仅仅是存在

3. **提供优先差距清单：**
  - 缺少强制性程序
  - 不完整的程序
  - 现有文件的质量问题
  - 缺少记录或表格

4. **创建补救计划：**
  - 高优先级：安全相关、监管要求
  - 中优先级：核心 QMS 流程
  - 低优先级：改进机会

### 场景 3：创建特定文档

 * *用户请求：**“帮我创建 CAPA程序。“

* *方法：**

1. **解释要求：**
  - 从参考文献中阅读 ISO 13485 第 8.5.2 和 8.5.3 条
  - 解释 CAPA 程序中必须包含的内容
  - 提供良好 CAPA 流程的示例

2. **使用模板：**
  - 从CAPA程序模板开始
  - 解释每个部分的目的
  - 显示需要定制的内容

3. **收集用户特定信息：**
  - 如何在其组织中启动 CAPA？
  - 谁是责任方？
  - 哪些优先级标准有意义？
  - 他们将使用什么 RCA 方法？
  - 适当的时间范围是什么？

4. **创建自定义过程：**
  - 替换所有占位符
  - 适应用户的流程
  - 确保完整性

5. **添加支持材料：**
  - CAPA 申请表
  - RCA 工作表
  - 行动计划模板
  - 有效性验证清单

### 场景 4：更新监管变更

 * *用户请求：** “我们需要更新 FDA QMSR 的 QMS协调。”

* *方法：**

1. **解释变更：**
  - FDA 21 CFR 第 820 部分与 ISO 13485
 协调一致 - 现在称为 QMSR（2026 年 2 月 2 日生效）
 - 关键变更：医疗器械文件取代了 DHF/DMR/DHR

2. **查看当前文档：**
  - 识别引用 QSR
 的文档 - 查找单独的 DHF、DMR、DHR 结构
 - 检查 ISO 13485 合规性差距

3. **更新策略：**
  - 将引用从 QSR 更新为 QMSR
  - 将 DHF/DMR/DHR 合并到医疗器械文件中 
  - 添加任何缺失的 ISO 13485 要求
  - 在过渡期间保持向后兼容性

4. **创建过渡计划：**
  - 更新质量手册
  - 更新MDF程序
  - 重新组织设备历史文件
  - 对人员进行变更培训

### 场景5：准备认证审核

 * *用户请求：**“我们已准备好文档。我们如何准备认证审核？”

* *方法：**

1. **进行准备情况评估：**
  - 使用全面的差距分析清单
  - 检查所有文档的完整性
  - 验证所有必需项目是否存在记录
  - 检查实施是否一致

2. **预审核清单：**
  - [ ]所有 31 项程序均已记录并获得批准
  - [ ]质量手册包含所有必需内容
  - [ ]所有产品的医疗器械文件完整
  - [ ]内部审核已完成并已解决问题
  - [ ]管理评审已完成
  - [ ]受过 QMS 程序培训的人员
  - [ ]根据保留要求维护记录
  - [ ] CAPA 系统正常运行并显示有效性
  - [ ]投诉系统可运行

3. **进行模拟审核：**
  - 使用ISO 13485要求作为审核标准
  - 样本记录以验证一致的实施
  - 与人员面谈以验证理解情况
  - 识别任何不符合项

4. **地址发现：**
  - 纠正任何缺陷
  - 文档更正
  - 验证有效性

5. **最终准备：**
  - 简要介绍管理人员和工作人员
  - 准备审核时间表
  - 整理证据和记录
  - 指定护送和支持人员

## 最佳实践

### 文档开发

1. **从政策级别开始，然后添加详细信息：**
  - 质量手册 = 政策级别
  - 程序 = 内容、人员、时间
  - 工作说明 = 详细操作方法
  - 表格 = 数据收集

2. **保持一致性：**
  - 始终使用相同的术语
  - 交叉引用相关文档
  - 保持编号方案一致
  - 一起更新所有相关文档

3. **为您的受众撰写：**
  - 清晰、简单的语言
  - 避免行话
  - 定义技术术语
  - 提供有用的示例

4. **使程序可用：**
  - 面向行动的语言
  - 逻辑流程
  - 明确的职责
  - 现实的时间框架

### 排除

 * *何时可以排除：**
  - 设计和开发（如果合同制造商）仅）
- 安装（如果产品不需要安装）
- 维修（如果未提供）
- 灭菌（如果非无菌产品）

* *理由要求：**
- 必须在质量手册中
- 必须解释为什么排除
- 不能排除，如果执行的流程
- 不会影响提供安全、有效设备的能力

* *良好理由示例：**
> “不包括第 7.3 条设计和开发。ABC 公司作为合同制造商运营，根据客户提供的完整设计规范生产医疗器械。所有设计活动均由客户执行，ABC 公司对设计输入、输出、验证、验证或设计变更不承担任何责任。”

* *不良理由示例：**
> “我们不这样做设计。” （太简短，无法解释原因或证明没有影响）

### 要避免的常见错误

1. **逐字复制 ISO 13485 文本**
  - 用您自己的话书写
  - 描述您的流程
  - 使其对您的组织可操作

2. **程序过于详细**
  - 程序应该稳定
  - 过多的细节属于工作指导
  - 平衡指导与灵活性

3. **单独创建文档**
  - 确保 QMS
 之间的一致性 - 交叉引用相关文档

### 关键监管要求

* *FDA（美国）：**
- 21 CFR 第 820 部分（现为 QMSR）- 自 2 月起与 ISO 13485 协调一致2026
- 器械分类确定要求
- 需要企业注册和器械列名

* *EU（欧盟）：**
- MDR 2017/745（医疗器械法规）
- IVDR 2017/746（体外诊断）规）
- 技术文件要求
- CE标志要求

* *加拿大：**
- 加拿大医疗器械法规 (SOR/98-282)
- 器械分类系统
- 医疗器械企业许可证 (MDEL)

* *其他地区：**
- 澳大利亚 TGA、日本 PMDA、中国 NMPA 等。
- 经常要求或认可 ISO 13485 认证

### 文档保留

* *最小保留：** 组织定义的医疗器械使用寿命

* *典型保留期限：**
- 设计文件：器械使用寿命 + 5-10 年
- 制造记录：器械使用寿命
- 投诉记录：器械使用寿命 + 5-10 年
- CAPA 记录：最少 5-10 年
- 校准记录：设备保留期 + 1 个校准周期

* *始终遵守可能指定更长期限的适用法规要求。**
