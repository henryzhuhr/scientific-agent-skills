# 知识图推理

## 概述

知识图以图的形式将结构化信息表示为实体和关系。 TorchDrug 使用基于嵌入的模型和神经推理方法为知识图补全（链接预测）提供全面支持。

## 可用数据集

### 通用知识图

* *FB15k（Freebase 子集）：**
- 14,951 个实体
- 1,345 个关系类型
- 592,213 个三元组
- Freebase 中的一般知识

* *FB15k-237:**
- 14,541 个实体
- 237 个关系类型
- 310,116 个三元组
- 删除反向关系的过滤版本
- 更具挑战性的基准

* *WN18（WordNet）：**
- 40,943个实体（词义）
- 18个关系类型（词汇关系）
- 151,442个三元组
- 语言知识graph

* *WN18RR:**
- 40,943 个实体
- 11 种关系类型
- 93,003 个三元组
- 过滤后的WordNet 删除简单的逆模式

### 生物医学知识图

* *Hetionet：**
- 45,158 个实体（基因、化合物、疾病、途径等）
- 24 个关系类型（治疗、原因、结合等）
- 2,250,197 个边
- 集成 29 个公共生物医学数据库
- 专为药物再利用和疾病理解而设计

## 任务：KnowledgeGraphCompletion

知识图的主要任务是链接预测 - 给定头部实体和关系，预测尾部实体（反之亦然）。

### 任务模式

* *头部预测：**
- 给定 (?,关系，尾部），预测头部实体
- “什么会导致疾病X？”

* *尾部预测：**
- 给定（头，关系，？），预测尾部实体
- “基因X导致什么疾病？”

* *两者：**
- 预测头部和尾部实体tail
- 标准评估协议

### 评估指标

* *排名指标：**
- **平均排名 (MR)**：正确实体的平均排名
- **平均倒数排名 (MRR)**：1/排名的平均值
- **Hits@K**：前 K 个预测中正确实体的百分比
  - 通常针对 K=1、3、 10

* *过滤与原始：**
- **过滤**：从排名中删除其他已知的真实三元组
- **原始**：在所有可能的实体中排名
- 过滤是评估标准

## 嵌入模型

### 翻译模型

* *TransE（翻译）嵌入）：**
- 将关系表示为嵌入空间中的翻译
- h + r ≈ t（头 + 关系 ≈ 尾）
- 简单有效的基线
- 适用于 1 对 1 关系
- 与 N 到 N 的斗争关系

* *RotatE（旋转嵌入）：**
- 复杂空间中的旋转关系
- 更好地处理对称和逆关系
- 在许多基准上都是最先进的
- 可以对组合模式进行建模

### 语义匹配模型

* *DistMult：**
- 双线性评分函数
- 自然处理对称关系
- 无法建模不对称关系
- 快速且内存高效

* *ComplEx：**
- 复值嵌入
- 建模不对称和逆关系
- 对于大多数图来说比DistMult 更好
- 平衡表达性和效率

* *SimplE:**
- 使用逆关系扩展DistMult
- 完全表达（可以表示任何关系）模式）
- 每个实体两个嵌入（规范和逆）

### 神经逻辑模型

* *NeuralLP（神经逻辑编程）：**
- 通过可微操作学习逻辑规则
- 通过学习规则解释预测
- 有利于稀疏知识图
- 计算上更昂贵

* *KBGAT（知识库图注意）：**
- 用于KG完成的图注意网络
- 从邻域学习实体表示
- 通过归纳学习处理看不见的实体
- 更好地处理不完整的图

## 训练工作流程

### 基本Pipeline

```python
from torchdrug import datasets, models, tasks, core

# Load dataset
dataset = datasets.FB15k237("~/kg-datasets/")

# Define model
model = models.RotatE(
    num_entity=dataset.num_entity,
    num_relation=dataset.num_relation,
    embedding_dim=2000,
    max_score=9
)

# Define task
task = tasks.KnowledgeGraphCompletion(
    model,
    num_negative=128,
    adversarial_temperature=2,
    criterion="bce"
)

# Train with PyTorch Lightning or custom loop
```

### 负采样

* *策略：**
- **均匀**：随机均匀采样实体
- **自对抗**：按当前模型的分数对样本进行加权
- **类型约束**：仅样本有效关系的实体类型

* *参数：**
- `num_negative`：每个正三元组的负样本数
- `adversarial_temperature`：自我对抗权重的温度
- 更高的温度=更关注硬负数

### 损失功能

* *二元交叉熵（BCE）：**
- 独立对待每个三元组
- 正负之间的平衡分类

* *边际损失：**
- 确保正分数比负分数高出边际
- `max(0, margin + score_neg - score_pos)`

* *Logistic Loss：**
- 平滑版的边际损失
- 更好的梯度属性

## 模型选择指南

### 按关系模式

* *1 对1 关系：**
- TransE 有效好吧
- 任何模型都可能成功

* *1对N关系：**
- DistMult、ComplEx、SimplE
- 避免TransE

* *N对1关系：**
- DistMult、ComplEx、 SimplE
- 避免 TransE

* *N 到 N 关系：**
- ComplEx、SimplE、RotatE
- 最具挑战性的模式

* *对称关系：**
- DistMult、Complex
- RotatE正确初始化

* *反对称关系：**
- ComplEx、SimplE、RotatE
- 避免 DistMult

* *逆关系：**
- ComplEx、SimplE、RotatE
- 对于双向很重要推理

* *组成：**
- RotatE（最佳）
- TransE（合理）
- 捕获多跳路径

### 按数据集特征

* *小图（< 50k）实体）：**
- ComplEx 或 SimplE
- 较低的嵌入尺寸 (200-500)

* *大型图（> 100k 实体）：**
- DistMult 提高效率
- RotatE 提高准确性
- 更高维度 (500-2000)

* * 稀疏图：**
- NeuralLP（从有限的学习规则）数据）
- 在较大的图上预训练嵌入

* *密集、完整的图：**
- 任何嵌入模型都可以很好地工作
- 基于关系模式进行选择

* *生物医学/领域图：**
- 在采样中考虑类型约束
- 使用特定领域的负采样
- Hetionet受益于关系特定模型

## 高级技术

### 多跳推理

链接多个关系来回答复杂的查询：
- “什么药物治疗由基因X引起的疾病？”
- 需要基于路径或基于规则推理
- NeuralLP自然支持这个

### 时态知识图

扩展到时变事实：
- 向三元组添加时态信息
- 预测未来事实
- 需要在模型中进行时态编码

### Few-Shot学习

用几个例子处理关系：
- 元学习方法
- 从相关关系转移
- 对新兴知识很重要

### 归纳学习

泛化到看不见的实体：
- KBGAT和其他基于GNN的方法
- 使用实体特征/描述
- 对于发展知识图至关重要

## 生物医学应用

### 药物再利用

预测Hetionet中的“药物治疗疾病”链接：
1. 对已知的药物-疾病关联 
2 进行培训。预测新的候选治疗方法
3. 按机制（基因、途径参与）过滤 
4. 通过实验验证预测

### 疾病基因发现

识别与疾病相关的基因：
1. 模型基因疾病途径网络
2. 预测缺失的基因疾病链接
3. 纳入蛋白质相互作用、表达数据
4. 优先考虑候选验证

### 蛋白质功能预测

将蛋白质与生物过程联系起来：
1. 整合蛋白质相互作用，GO术语
2. 预测缺失的 GO 注释
3. 来自相似蛋白质的传递函数

## 常见问题和解决方案

* *问题：在特定关系类型上性能较差**
- 解决方案：分析关系模式，选择合适的模型，或使用关系特定模型

* *问题：小图上的过度拟合**
- 解决方案：减少嵌入维度，增加正则化，或使用更简单的模型models

* *问题：在大图上训练速度慢**
- 解决方案：减少负样本，使用 DistMult 提高效率，或实现小批量训练

* *问题：无法处理新实体**
- 解决方案：使用归纳模型（KBGAT），合并实体特征，或根据新实体预先计算嵌入邻居

## 最佳实践

1. 对于大多数任务，从 ComplEx 或 RotatE 开始 
2. 使用自对抗负采样
3. 调整嵌入尺寸（通常为500-2000）
4. 应用正则化以防止过度拟合
5. 使用过滤后的评估指标
6. 分析每个关系类型的性能
7. 考虑异构图的关系特定模型
8. 与领域专家验证预测
