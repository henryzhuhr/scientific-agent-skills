# 科学假设生成

## 概述

H假设生成是开发可检验解释的系统过程。根据观察形成基于证据的假设、设计实验、探索相互竞争的解释并做出预测。将此技能应用于跨领域的科学探究。

## 何时使用此技能

此技能应在以下情况下使用：
- 根据观察或初步数据提出假设
- 设计实验来测试科学问题
- 探索现象的相互竞争的解释
- 为研究制定可测试的预测
- 进行基于文献的假设生成
- 规划跨科学领域的机制研究

## 科学示意图的视觉增强

2. 优先使用 2-3 个图表进行综合报告（机制路径、实验设计流程图、预测决策树）

## 工作流程

遵循此系统流程生成可靠的科学假设：

### 1.理解现象

首先澄清需要的观察、问题或现象解释：

- 确定需要解释的核心观察或模式
- 定义现象的范围和边界
- 注意任何限制或特定背景
- 澄清已知与不确定的内容
- 确定相关的科学领域

### 2. 进行综合文献搜索

搜索现有科学文献，根据当前证据提出假设。使用 PubMed（针对生物医学主题）和一般网络搜索（针对更广泛的科学领域）：

* *针对生物医学主题：**
- 使用 WebFetch 和 PubMed URL 访问相关文献
- 搜索最近的评论、荟萃分析和初步研究
- 查找类似的现象、相关机制或类似的系统

* *适用于所有科学领域：**
- 使用网络搜索查找最近的论文、预印本和评论
- 搜索已建立的理论、机制或框架
- 找出当前理解中的差距

* *搜索策略：**
- 从广泛搜索开始以了解景观
- 缩小到特定的机制、途径或理论
- 寻找矛盾的发现或未解决的争论
- 咨询`references/literature_search_strategies.md` 了解详细的搜索技术

### 3. 综合现有证据

分析并整合文献检索的结果：

- 总结当前对现象的理解
- 确定可能适用的既定机制或理论
- 记下相互矛盾的证据或替代观点
- 认识差距、局限性或未解答的问题
- 确定来自相关系统或领域的类比

### 4. 生成竞争假设

提出 3-5 个可以解释该现象的不同假设。每个假设应该：

- 提供机制解释（不仅仅是描述）
- 与其他假设区分开来
- 利用文献综合中的证据
- 考虑不同层次的解释（分子、细胞、系统、群体等）

* *生成的策略假设：**
- 应用类似系统中的已知机制
- 考虑多种因果途径
- 探索不同尺度的解释
- 现有解释中的问题假设
- 以新颖的方式组合机制

### 5. 评估假设质量

根据`references/hypothesis_quality_criteria.md`的既定质量标准评估每个假设：

* *可检验性：**可以对假设进行实证检验吗？
* *可证伪性：**什么观察结果会反驳它？
* *简洁性：**这是符合证据的最简单的解释吗？
* *解释力：**它解释了多少现象？
* *范围：**它涵盖了哪些观察范围？
* *一致性：**它是否符合既定原则？
* *新颖性：**它是否提供了超出现有解释的新见解？

明确指出每个假设的优点和缺点。

### 6. 设计实验测试

对于每个可行的假设，提出具体的实验或研究来测试它。常用方法请咨询`references/experimental_design_patterns.md`：

* *实验设计元素：**
- 将测量或观察什么？
- 需要哪些比较或对照？
- 将使用哪些方法或技术？
- 哪些样本量或统计方法合适？
- 什么是潜在的混淆以及如何解决它们？

* *考虑多个方法：**
- 实验室实验（体外、体内、计算）
- 观察研究（横断面、纵向、病例对照）
- 临床试验（如果适用）
- 自然实验或准实验设计

### 7. 制定可检验的预测

对于每个假设，生成具体的定量预测：

- 说明假设正确时应观察到的情况
- 在可能的情况下指定预期影响的方向和幅度
- 确定预测应成立的条件
- 区分相互竞争的假设之间的预测
- 注意会证伪假设的预测

### 8.呈现结构化输出

使用`assets/hypothesis_report_template.tex`中的模板生成专业的LaTeX文档。报告应采用良好的格式，用彩色框进行视觉组织，并分为简洁的正文和全面的附录。

* *文件结构：**

* *正文（最多4页）：**
1. **执行摘要** - 摘要框中的简要概述（0.5-1 页）
2. **竞争假设** - 每个假设在其自己的彩色框中，带有简短的机制解释和关键证据（3-5 个假设的 2-2.5 页）
  - **重要：** 在每个假设框之前使用 `\newpage` 以防止内容溢出
  - 每个框最多应≤0.6 页
3. **可测试的预测** - 琥珀色框中的关键预测（0.5-1 页）
4. **关键比较** - 优先级比较框（0.5-1 页）

保持正文高度简洁——仅包含最重要的信息。所有详细信息请参见附录。

* *分页策略：**
- 始终在假设框之前使用 `\newpage`，以确保它们在新页面上开始
- 这可以防止内容溢出页面边界
- LaTeX 框（tcolorbox）不会自动跨页分隔

* *附录（综合，详细）：**
- **附录 A：** 广泛引用的综合文献综述
- **附录 B：** 详细的实验设计和完整方案
- **附录 C：** 质量评估表和详细评估
- **附录 D：** 补充证据和类似系统

  * *彩色框用法：**

使用 `hypothesis_generation.sty` 中的自定义框环境：

- `hypothesisbox1` 到 `hypothesisbox5` - 对于每个竞争假设（蓝色、绿色、紫色、青色、橙色）
- `predictionbox` - 用于可测试的预测（琥珀色）
- `comparisonbox` - 用于关键比较（钢灰色）
- `evidencebox` - 用于支持证据突出显示（浅蓝色）
- `summarybox` - 用于执行摘要（蓝色）

* *每个假设框应包含（在 4 页限制中保持简洁）：**
- **机制解释：** 1-2 个简短段落（最多 6-10 句话）解释如何和为何
- **关键支持证据：** 2-3 个带引文的要点（仅最重要的证据）
- **核心假设：** 1-2 个关键假设

所有详细解释、附加证据和全面讨论都属于附录.

* *关键溢出预防：**
- 在每个假设框之前插入 `\newpage`，以在新页面上开始它 
- 将每个完整的假设框保持在 ≤0.6 页（大约 15-20 行内容） 
- 如果内容超出此范围，请将其他详细信息移动到附录 A
- 切勿让框溢出页面边界 - 这会导致不可读PDFs

* *引文要求：**

旨在广泛引用以支持所有主张：
- **正文：** 仅针对最重要的证据进行 10-15 个关键引文（4 页限制保持简洁）
- **附录 A：** 涵盖所有相关文献的 40-70+ 综合引文
- **总目标：** 参考书目中有 50 多篇参考文献

 主要文本引用应该是有选择性的 - 只引用最关键的论文。所有全面的引用和详细的文献讨论都包含在附录中。使用 `\citep{author2023}` 进行括号引用。

* *LaTeX 编译：**

 模板需要 XeLaTeX 或 LuaLaTeX 才能正确渲染：

```bash
xelatex hypothesis_report.tex
bibtex hypothesis_report
xelatex hypothesis_report.tex
xelatex hypothesis_report.tex
```

* *所需包：** `hypothesis_generation.sty` 样式包必须位于同一目录或乳胶路径。它需要：tcolorbox、xcolor、fontspec、fancyhdr、titlesec、enumitem、booktabs、natbib。

* *页面溢出预防：**

要防止内容在页面上溢出，请遵循以下关键准则：

1. **监控框内容长度：** 每个假设框应舒适地放在一页上。如果内容超过约 0.7 页，则可能会溢出。

2. **使用策略性分页符：** 在包含实质性内容的框之前插入 `\newpage`：
 ```latex
 \newpage
 \begin{hypothesisbox1}[假设 1：标题]
 % 此处长内容
 \end{假设框1}
 ```

3. **保持正文框简洁：** 对于 4 页正文限制：
  - 每个假设框：最多 0.5-0.6 页
  - 机制解释：仅 1-2 个简短段落（最多 6-10 个句子）
  - 关键证据：仅 2-3 个要点
  - 核心假设：1-2 项only
  - 如果内容较长，请将详细信息移至附录

4. **详细内容：** 如果假设需要广泛解释，请分为正文和附录：
  - 主文本框：简要机制概述 + 2-3 个关键证据点
  - 附录 A：详细机制解释、全面证据、扩展讨论

5. **测试页面边界：** 在每个新框之前，请考虑剩余页面空间是否足够。如果剩余页数少于 0.6 页，请使用 `\newpage` 在新页面上启动该框。

6. **附录页面管理：** 在附录中，在主要部分之间使用 `\newpage` 以避免详细内容区域溢出。

* *快速参考：** 有关所有框类型、配色方案和常见格式模式的详细示例，请参阅 `assets/FORMATTING_GUIDE.md`。

## 质量标准

确保所有生成的假设满足这些标准：

- **基于证据：** 以现有文献为基础并引用
- **可测试：** 包括具体的、可测量的预测
- **机制：** 解释如何/为什么，而不仅仅是什么
- **全面：** 考虑替代解释
- **严格：** 包括实验设计测试预测
