# 科学批判性评估和同行评审

## 概述

同行评审是评估科学稿件的系统过程。评估方法、统计、设计、再现性、道德和报告标准。通过建设性、严格的评估，将此技能应用于跨学科的手稿和拨款审查。

## 何时使用此技能

此技能应在以下情况下使用：
- 对期刊的科学手稿进行同行评审
- 评估拨款提案和研究申请
- 评估方法和实验设计的严谨性
- 审查统计分析和报告标准
- 评估再现性和数据可用性
- 检查是否符合报告指南（CONSORT、STROBE、PRISMA）
- 提供有关科学写作的建设性反馈

## 同行评审工作流程

通过以下阶段系统地进行同行评审，根据稿件类型和学科调整深度和重点。

### 第 1 阶段：初步评估

开始进行高级评估，以确定稿件的

* *关键问题：**
- 中心研究问题或假设是什么？
- 主要发现和结论是什么？
- 这项工作是否科学合理且有意义？
- 该工作是否适合预期地点？
- 是否存在任何直接的重大缺陷，会导致

* *输出：** 简短摘要（2-3句话）捕捉手稿的本质和初步印象。

### 阶段2：详细的逐节审查

对每个手稿部分进行彻底评估，记录具体的关注点和优势。

#### 摘要和标题
- **准确性：**摘要准确地反映了研究的内容和结论？
- **清晰度：** 标题是否具体、准确且信息丰富？
- **完整性：** 主要发现和方法是否得到适当总结？
- **可访问性：** 摘要是否能为广大科学受众所理解？

#### 简介
- **背景：** 背景信息是否充分且最新？
- **基本原理：** 研究问题是否有明确的动机和合理性？
- **新颖性：** 是否清楚地阐明了工作的原创性和意义？
- **文献：** 是否适当引用了相关的先前研究？
- **目标：** 是明确阐述研究目标/假设？

#### 方法
- **再现性：** 其他研究人员能否根据提供的描述复制研究？
- **严谨性：** 方法是否适合解决研究问题？
- **详细信息：** 方案、试剂、设备和参数是否得到充分描述？
- **道德：** 符合道德标准批准、同意和数据处理是否正确记录？
- **统计：** 统计方法是否适当、清晰描述和合理？
- **验证：** 对照、重复和验证方法是否足够？

* *要验证的关键要素：**
- 样本量和功效计算
- 随机化和盲法程序
- 纳入/排除标准
- 数据收集协议
- 计算方法和软件版本
- 多重比较的统计测试和校正

#### 结果
- **演示：** 结果是否逻辑清晰地呈现？
- **图/表：** 可视化是否适当、清晰且正确标记？
- **统计：** 统计结果是否正确报告（效应大小、置信区间、p 值）？
- **客观性：** 结果是否在没有过度解释的情况下呈现？
- **完整性：** 是否包含所有相关结果，包括阴性结果？
- **再现性：** 是否提供原始数据或汇总统计数据？

* *需要识别的常见问题：**
- 选择性报告结果
- 不适当的统计测试
- 缺少误差线或变异性测量
- 过度拟合或循环分析
- 批次效应或混杂变量
- 缺少对照或验证实验

#### 讨论
- **解释：** 结论是否得到数据支持？
- **局限性：** 是否承认并讨论了研究的局限性？
- **背景：** 研究结果是否适当地放置在现有文献中？
- **推测：** 推测是否与数据支持的结论明确区分开来？
- **意义：** 含义和重要性是否清楚阐明？
- **未来方向：** 是否讨论了下一步或未回答的问题？

* *危险信号：**
- 夸大结论
- 忽略矛盾证据
- 相关数据中的因果主张
- 讨论不充分局限性
- 没有机械证据的机械论断

#### 参考文献
- **完整性：** 是否引用了关键相关论文？
- **货币：** 是否包括最近的重要研究？
- **平衡：** 是否适当引用了相反的观点？
- **准确性：** 是引用准确且适当？
- **自引：** 是否存在过度或不适当的自引？

### 第 3 阶段：方法和统计严谨性

E 评估研究的技术质量和严谨性，特别注意常见陷阱。

* *统计评估：**
- 是否满足统计假设（正态性、独立性、同方差性）？
- 效应大小是否与 p 值一起报告？
- 是否适当应用了多重检验校正？
- 是否提供了置信区间？
- 样本大小是否通过功效分析进行了合理化？
- 是参数还是参数？是否正确选择了非参数检验？
- 缺失数据处理是否正确？
- 探索性分析与验证性分析是否有区别？

* *实验设计：**
- 控制是否适当且充分？
- 复制是否足够（生物学和技术）？
- 是否识别并确定了潜在的混杂因素？受控吗？
- 随机化是否正确实施？
- 盲法程序是否足够？
- 实验设计是否适合研究问题？

* *计算/生物信息学：**
- 计算方法是否清楚描述和合理？
- 软件版本和参数是否正确
- 代码是否可用于再现性？
- 算法和模型是否经过适当验证？
- 计算方法的假设是否得到满足？
- 批量校正是否得到适当应用？

### 第 4 阶段：再现性和透明度

评估研究是否符合现代标准

* *数据可用性：**
- 原始数据是否存放在适当的存储库中？
- 是否为公共数据库提供了登录号？
- 数据共享限制是否合理（例如患者隐私）？
- 数据格式是否标准且可访问？

* *代码和材料：**
- 是否提供分析代码（GitHub、Zenodo 等）？
- 是否有独特的材料可用或描述足够用于娱乐？
- 协议是否有足够深度的详细说明？

* *报告标准：**
- 稿件是否遵循特定学科的报告指南（CONSORT、PRISMA、ARRIVE、MIAME、MINSEQE 等）？
- 请参阅 `references/reporting_standards.md` 了解通用指南
- 是否解决了相应检查表的所有元素？

### 第 5 阶段：图形和数据演示 

E 评估数据可视化的质量、清晰度和完整性。

* *质量检查：**
- 图形是否高分辨率且标记清晰？
- 轴是否正确标记了单位？
- 是否定义了误差线（SD、SEM、CI）？
- 是否解释了统计显着性指标？
- 是配色方案适当且易于访问（色盲友好）？
- 图像是否包含比例尺？
- 数据可视化是否适合数据类型？

* *完整性检查：**
- 是否有图像操作的迹象（重复、拼接）？
- 蛋白质印迹和凝胶是否适当
- 代表性图像是否真正具有代表性？
- 是否显示了所有条件（无选择性呈现）？

* *清晰度：**
- 图形可以独立于其图例吗？
- 每个图形的信息是否立即清晰？
- 是否有多余的图形或面板？
- 会数据更好地以表格或图形的形式呈现？

### 第 6 阶段：道德考虑

验证研究是否符合道德标准和指南。

* *人类受试者：**
- IRB/伦理批准是否有记录？
- 是否描述了知情同意？
- 弱势群体是否适当受保护？
- 患者隐私是否得到充分保护？
- 是否披露了潜在的利益冲突？

* *动物研究：**
- IACUC 或同等批准是否有记录？
- 程序是否人道且合理？
- 是否是 3R（替换、减少、细化）考虑过吗？
- 安乐死方法合适吗？

* *研究诚信：**
- 是否担心数据伪造或伪造？
- 作者身份是否适当且合理？
- 是否披露了竞争利益？
- 是否披露了资金来源？
- 是否担心剽窃或重复发表？

### 第 7 阶段：写作质量和清晰度

评估手稿的清晰度、组织和可访问性。

* *结构和组织：**
- 手稿的组织是否符合逻辑？
- 章节是否连贯？
- 思想之间的过渡是否清晰？
- 叙述是否引人注目且清晰？

* *写作质量：**
- 语言是否清晰、准确、简洁？
- 行话和缩略语是否被最小化和定义？
- 语法和拼写是否正确？
- 句子是否不必要地复杂？
- 是被动语态过度使用？

* *可访问性：**
- 非专业人士能否理解主要发现？
- 技术术语是否得到解释？
- 其重要性对广大受众来说是否清楚？

## 构建同行评审报告

以分层结构组织反馈，优先考虑问题并提供可操作的信息

### 摘要陈述

提供简明的总体评估（1-2段）：
- 研究简要概要
- 总体建议（接受、小修改、大修改、拒绝）
- 主要优点（2-3 个要点）
- 主要弱点（2-3）要点）
- 重要性和健全性的底线评估

### 主要评论

列出显着影响手稿有效性、可解释性或重要性的关键问题。按顺序编号以便于参考。

* *主要评论通常包括：**
- 基本方法缺陷
- 不适当的统计分析
- 不受支持或夸大的结论
- 缺少关键控制或实验
- 严重的再现性问题
- 文献覆盖率的主要差距
- 道德关注点

* *对于每条主要评论：**
1. 明确说明问题
2. 解释一下为什么有问题
3. 建议具体的解决方案或额外的实验
4. 指出解决该问题对于出版是否至关重要

### 次要评论

列出可以提高清晰度、完整性或演示效果的不太重要的问题。按顺序编号。

* *次要评论通常包括：**
- 不清楚的图形标签或图例
- 缺少方法细节
- 印刷或语法错误
- 改进数据表示的建议
- 次要统计报告问题
- 补充分析将加强结论
- 要求澄清

* *对于每条小评论：**
1. 标明具体位置（节、段、图）
2. 把问题说清楚
3. 建议如何解决

### 具体逐行注释（可选）

对于需要详细反馈的稿件，提供特定部分或逐行注释：
- 参考特定页/行号或部分
- 注意事实错误、不清楚的陈述或缺失的引文
- 建议具体编辑清晰度

### 作者问题

列出需要澄清的具体问题：
- 方法细节不清楚
- 看似矛盾的结果
- 缺少评估工作所需的信息
- 要求额外数据或分析

## 语气和方法

在整个审查过程中保持建设性、专业和合议的语气。

* *最佳实践：**
- **具有建设性：** 将批评视为改进的机会
- **具体：** 提供具体示例和可行的建议
- **保持平衡：** 承认优点和缺点
- **尊重：** 记住作者付出了巨大的努力
- **客观：** 关注科学，而不是事实科学家
- **彻底：**不要忽视问题，但要适当地确定优先顺序
- **明确：**避免模棱两可或模糊的批评

* *避免：**
- 人身攻击或轻蔑的语言
- 讽刺或居高临下
- 没有具体例子的模糊批评
- 请求超出范围的不必要实验
- 要求遵守个人喜好与最佳实践
- 如果审稿是双盲的，则暴露你的身份

## 稿件类型的特殊考虑

### 原创研究文章
- 强调严谨性、可重复性和新颖性
- 评估重要性和影响
- 验证结论是数据驱动的
- 检查完整的方法和适当的控制

### 评论和荟萃分析
- 评估文献覆盖的全面性
- 评估搜索策略和纳入/排除标准
- 验证系统方法和缺乏偏差
- 检查关键分析与单纯总结
- 用于荟萃分析，评估统计方法和异质性

### 方法论文
- 强调与现有方法的验证和比较
- 评估协议/代码的再现性和可用性
- 评估对现有方法的改进方法
- 检查实施是否有足够的细节

### 简短报告/信件
- 调整期望以简洁
- 确保核心调查结果仍然严格且重要
- 验证格式是否适合调查结果

### 预印本
- 认识到这些尚未经过正式的同行评审
- 可能不如期刊提交
- 仍然采用严格的科学有效性标准
- 考虑提供建设性反馈以帮助作者在期刊提交之前改进

### 演示文稿和幻灯片

* *⚠️ 关键：对于演示文稿中，切勿直接阅读 PDF。始终先转换为图像。**

审阅科学演示文稿（PowerPoint、Beamer、幻灯片）时：

#### 强制基于图像的审阅工作流程

* *切勿尝试直接读取演示文稿 PDF** - 这会导致缓冲区溢出错误，并且不会显示视觉格式问题。

* *所需过程：**
1. 使用 Python 将 PDF 转换为图像：
 ```bash
 python Skills/scientific-slides/scripts/pdf_to_images.pypresentation.pdf review/slide --dpi 150
 # 创建：review/slide-001.jpg、review/slide-002.jpg、等
```
2. 按顺序读取并检查每个幻灯片图像文件
3. 记录特定幻灯片编号
4 的问题。提供有关视觉格式和内容的反馈

* *开始审阅时打印：**
```
[HH:MM:SS] PEER REVIEW: Presentation detected - converting to images for review
[HH:MM:SS] PDF REVIEW: NEVER reading PDF directly - using image-based inspection
```

#### 演示特定评估标准

* *视觉设计和可读性：**
- [ ]文本足够大（最小 18pt，理想情况下正文为 24pt+）文本）
- [ ]文本和背景之间的高对比度（最低 4.5:1，首选 7:1）
- [ ]配色方案专业且色盲人士也可使用
- [ ]所有幻灯片的视觉设计一致
- [ ]空白足够（不拥挤）
- [ ]字体清晰专业

* *布局和格式（检查每张幻灯片图像）：**
- [ ]幻灯片边缘没有文本溢出或截断
- [ ]没有元素重叠（图像上的文本、形状重叠）
- [ ]标题位置一致
- [ ]内容正确对齐
- [ ]项目符号和文本未被剪切off
- [ ]数字适合幻灯片边界 
- [ ]标题和标签可见且可读 

* *内容质量：**
- [ ]每张幻灯片一个主要思想（未超载）
- [ ]最少文本（每张幻灯片最多 3-6 个项目符号）
- [ ]项目符号点为简洁（每个 5-7 个字）
- [ ]图表简化且清晰（不是从论文中复制粘贴）
- [ ]数据可视化有大而可读的标签 
- [ ]引文存在且格式正确 
- [ ]结果/数据幻灯片主导了演示（占 40-50% 的内容）内容）

* *结构和流程：**
- [ ]清晰的叙述弧（介绍 → 方法 → 结果 → 讨论）
- [ ]幻灯片之间的逻辑进展
- [ ]适合演讲持续时间的幻灯片数量（每分钟约 1 张幻灯片）
- [ ]标题幻灯片包括作者、所属单位、日期
- [ ]引言引用了相关背景文献（3-5 篇论文）
- [ ]讨论引用了比较论文（3-5 篇论文）
- [ ]结论幻灯片总结了主要发现
- [ ]致谢/资助幻灯片在最后

  * *科学内容：**
- [ ]明确阐述研究问题
- [ ]充分总结方法（不过分细节）
- [ ]结果以清晰的可视化逻辑呈现
- [ ]统计显着性适当
- [ ]由所示数据支持的结论
- [ ]承认的局限性在适当的情况下
- []讨论未来方向或更广泛的影响

* *关键问题（必须修复）：**
- 文本溢出导致内容不可读
- 字体太小 (<18pt)
- 元素重叠模糊数据
- 对比度不足（文本难以阅读）
- 数字太复杂或难以辨认
- 无引用（完全不受支持的声明）
- 幻灯片计数与持续时间严重不匹配

* *主要问题（应修复）：**
- 幻灯片之间的设计不一致
- 文本太多（文本墙，而不是项目符号）
- 简化的图形很差（轴标签太小）
- 狭窄空白空间不足的布局
- 缺少关键结构元素（无结论幻灯片）
- 颜色选择不佳（色盲不安全）
- 结果内容最少（幻灯片的30%以下）

* *小问题（改进建议）：**
- 可以使用更多视觉效果/图表
- 一些幻灯片文字较多
- 轻微对齐不一致
- 可以从更多的空白中受益
- 额外的引用将加强声明
- 配色方案可以更现代

#### 审查报告格式演示文稿

* *总结陈述：**
- 演示质量的总体印象
- 对目标受众和持续时间的适当性
- 主要优势（视觉设计、内容、清晰度）
- 主要弱点（格式问题、内容差距）
- 建议（准备演示、小修改、重大修改）修订）

* *布局和格式问题（按幻灯片编号）：**
```
Slide 3: Text overflow - bullet point 4 extends beyond right margin
Slide 7: Element overlap - figure overlaps with caption text
Slide 12: Font size - axis labels too small to read from distance
Slide 18: Alignment - title not centered
```

* *内容和结构反馈：**
- 背景上下文和引用的充分性
- 研究问题和目标的清晰度
- 方法的质量摘要
- 结果演示的有效性
- 结论和含义的强度

* *设计和可访问性：**
- 整体视觉吸引力和专业性
- 颜色对比度和可读性
- 色盲可访问性
- 幻灯片之间的一致性

* *时间和范围：**
- 幻灯片计数是否与预期持续时间匹配
- 演讲类型的适当细节水平
- 各部分之间的平衡
